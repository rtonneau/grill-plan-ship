# /gps auto Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `/gps auto [plan|ship|finish]` (alias `/gps write+finish`), which runs a session from its current phase to the target with one up-front question and no other stops.

**Architecture:** A pure routing function (`scripts/lib/auto-route.js`) turns the session's phase and the target into an ordered step list. A thin handler (`scripts/auto-route.js`) prints that list as JSON and records an `auto_started` event. A new `references/auto.md` tells Claude to run each step's existing reference file in order, with the overrides that remove the stops.

**Tech Stack:** Node.js (fs only, no dependencies), plain `assert` test scripts run by `npm test`.

**Spec:** `docs/superpowers/specs/2026-09-30-gps-auto-design.md`

## Global Constraints

- Handlers use Node's `fs` only; no new dependencies.
- Handler failures go through `runCli` / `GpsError`: `❌ <message>` then an indented hint, exit 1, no stack trace.
- Record the state change with `recordEvent` (`scripts/lib/history.js`) after validation succeeds; it never throws.
- Valid targets are exactly `plan`, `ship`, `finish`; default `finish`.
- Step names are exactly `write:grill`, `plan`, `write:plan`, `ship`, `finish`, in that order.
- `/gps write+plan` and `/gps write+ship` keep their current behavior.
- `SKILL.md` stays ≤ 70 lines; `write.md` stays ≤ 50 lines (both asserted in `handlers.test.js`; `write.md` is at 49 now).

## Review Focus

- A target with other casing or stray arguments (`/gps auto Finish`, `/gps auto ship finish`): expect a `❌` listing the valid targets, never a silent default. Tests in Tasks 1 and 2.
- A session already finished: `❌` saying so, before any question is asked. Test in Task 1.
- A target already passed (`auto plan` once the plan is written): `❌` naming the targets still reachable. Test in Task 1.
- A failed handler call must not record `auto_started`. Test in Task 2.
- `write+finish` with the grill already written must route like `auto finish` (starting at `plan`), not refuse. Covered by `auto.md` wording in Task 3.

- [ ] **Step 3: Implement `computeRoute` in `scripts/lib/auto-route.js`**
